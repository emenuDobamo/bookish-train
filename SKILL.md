# Skill: doc-reviewer

## Purpose
Provide a lightweight checklist for reviewing documentation changes so they stay clear, consistent, and easy to maintain.

## When to use
- A PR or task adds or updates README files, guides, or other Markdown docs.
- The user asks for a documentation quality review.

## Inputs
- Documentation files (Markdown or plain text).
- Optional context about target audience or tone.

## Steps
1. Verify the document has a clear title and logical heading hierarchy.
2. Check for concise, action-oriented bullet points.
3. Confirm terminology is consistent across sections.
4. Ensure examples or commands are accurate and complete.
5. Add or update references to related docs when needed.

## Outputs
- A short list of recommended edits.
- Confirmation when no issues are found.
